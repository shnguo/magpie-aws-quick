# Upstream decision log

This fork reviews changes from httpdone/magpie-aws-quick daily. The last upstream version merged in full was 0.1.9. Later features can reach the fork through individual backports, so the daily comparison starts at the last reviewed upstream commit. [0.1.9 merge into the fork](https://github.com/shnguo/magpie-aws-quick/commit/4dbfa5b90376a960cb2bc58385eca8d69628a0cc)

Each entry names the feature, its upstream source, the decision date, the reason and any fork commit that implements it. A pending item can include a recommendation. When a decision changes, append a dated entry so the earlier reasoning remains available. For a deferred change, record what would justify another look.

| Recover the decisions made on another account when a chat returns to its original account | Pending · recommend adapting first | When accounts A and B both replied “Acknowledged,” the fork resumed A with only “Continue now.” Upstream preserved B’s intervening decision. | Recover a complete tool call when its closing tag is missing | Pending · recommend adapting | PR #17 has merged upstream. It recovers complete nested arguments with a missing or partial closing tag. The fork drops that call. Upstream also accepted malformed argument strings as empty arguments in a fixture. Use the fork’s stricter parser and verify a single emitted call for complete arguments, including literal tags inside strings. Keep rejecting partial JSON. [Merged PR #17](https://github.com/httpdone/magpie-aws-quick/pull/17) · [Fork parser](https://github.com/shnguo/magpie-aws-quick/blob/75211fb31565ea77afde786ab795cc32ea11b39a/lib/tools.mjs) |
| Recheck an account during its quota cooldown | Pending · recommend adapting | The fork checks usage once at exhaustion. Upstream checks again when traffic arrives, at intervals of 3–30 minutes, so a recovered account can serve requests sooner. In fixtures, incomplete counters revived an account and two concurrent callers saw different results from the same recovery. Require evidence that the exhausted quota has recovered, share the result across callers, and retain the fork’s timeout, stale-response checks and later reset when both quotas are exhausted. [Upstream change](https://github.com/httpdone/magpie-aws-quick/commit/c2224ca4352e6a536f80b83ca1c6cb0dbf0fabc4) · [Fork cooldown](https://github.com/shnguo/magpie-aws-quick/blob/75211fb31565ea77afde786ab795cc32ea11b39a/lib/usage.mjs) |

Preserve the monthly display if the extra lookup fails or times out. [Usage card](https://github.com/httpdone/magpie-aws-quick/commit/9460c3063e98fbbe1070cf1c0c51a05de7a0a6d0) · [Reset corrections](https://github.com/httpdone/magpie-aws-quick/commit/17e7eb33dd25d04ee34b5450d1d0ece699633e95) |

### Adopted on 2026-11-26

The five pending entries above were approved in four groups and integrated as selective backports. [Fork implementation](https://github.com/shnguo/magpie-aws-quick/commit/b63c9aab5a6f32509bc8b81da156a3536641d21d)

| Feature | Decision and reason |
| --- | --- |
| Returning to an account after failover | Adopted with changes. An exact match on earlier history lets the adapter send intervening text exchanges to the original thread, even if both accounts gave the same reply. Intervening tools or images use fresh-thread replay to preserve call arguments, complete results and attachments. [Regression tests](https://github.com/shnguo/magpie-aws-quick/blob/b63c9aab5a6f32509bc8b81da156a3536641d21d/test/returning-account.test.mjs) |
| Tool calls with a missing or partial closing tag | Adopted with changes. A normally completed turn can deliver the call once when the JSON and arguments are valid. Interrupted turns and a local stop after a native call retain their existing handling to prevent accidental execution or duplicates. [Regression tests](https://github.com/shnguo/magpie-aws-quick/blob/b63c9aab5a6f32509bc8b81da156a3536641d21d/test/tool-call-recovery.test.mjs) |
| Rechecking quota during cooldown | Adopted with changes. Requests share a usage check when one is due. Incomplete or stale readings preserve existing constraints, and a fresh refusal takes precedence over an older recovery probe. This allows recovered accounts to resume early while keeping confirmed reset times intact. [Regression tests](https://github.com/shnguo/magpie-aws-quick/blob/b63c9aab5a6f32509bc8b81da156a3536641d21d/test/quota-recovery.test.mjs) |
| Usage display and HTTP 429 reset reporting | Adopted together so the account card and router use the same reset information. The card displays five-hour session minutes when available and retains monthly entitlements if the extra lookup times out. A cooldown response with a server-reported reset includes Retry-After in seconds, an absolute reset timestamp and the name of the limiting quota. [Usage-card tests](https://github.com/shnguo/magpie-aws-quick/blob/b63c9aab5a6f32509bc8b81da156a3536641d21d/test/usage.test.mjs) · [HTTP reset tests](https://github.com/shnguo/magpie-aws-quick/blob/b63c9aab5a6f32509bc8b81da156a3536641d21d/test/quota.test.mjs) |

All 292 tests passed separately on Node 22, 24 and 26. A live Quick Fast request through the worktree adapter returned the expected reply. The live usage hook reported valid counters for both the five-hour session and Agent hours, with a future monthly reset. Quota exhaustion and recovery were exercised with local fixtures.
